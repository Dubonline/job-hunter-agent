# BOSS智能投递助手 · job-hunter-agent

本地运行的 BOSS 岗位筛选与沟通助手：检索条件 → JD读取 → 规则/模型评审 → 收藏及沟通 → 每日分批简报。

项目处于早期阶段，欢迎通过 Issue 提出建议或通过 PR 改进。当前主要验证环境为 macOS、Chrome 和 Python 3.14；筛选选项有限，匹配判断仍需用户核对。

## 功能

- 接入用户已登录的 Chrome，单连接、断线停止，不自动登录或读取个人浏览器资料。
- 中文配置向导及隔离档案；PDF/DOCX本地提取、配置DeepSeek有据分析、用户确认保存。
- 固定筛选框展开、选择和状态核对；详情响应优先与DOM/OCR交叉核对，冲突停止。
- 可选模型评审与本地规则，薪资明文或本机OCR交叉核对。
- 显式启动后，高度契合收藏并沟通，通用岗位只沟通，成功后留在此页。
- 跨运行防重、未知结果停止、每日本机额度和分批简报。

## 项目亮点

- 从个人画像和真实项目场景出发评审岗位，近期项目优先、历史技能累积，不只按AI关键词命中；匹配质量仍待校准。
- PDF/DOCX先用本地中间件解析，再由配置的DeepSeek选取原文依据；草稿修改确认后保存，不让模型扩写新经历。
- 详情响应优先，DOM及本机薪资OCR核对/兜底；观察到岗位身份或数据冲突就停止。
- 发送意图先持久化、跨运行防重、未知结果停止；目标沟通人数与安全扫描上限分离，自动生成分批简报。

## 当前已知问题（待修）

- 未活跃HR尚无可靠的前置拦截，可能仍被沟通；活跃时间阈值需要依据真实标签确认。
- 已明确不适合的公司应在后续检测和投递前跳过；现有岗位防重及配置黑名单尚不能代替完整公司级排除。
- 用户反馈“不合适”尚未形成持久化排除闭环，不能保证同公司其他岗位被拦截。
- 任职条件核验不完整、画像证据与岗位要求的对应可能失准：系统可能过度依赖职责或关键词的相关性，遗漏必备技能、行业经验等要求，或在缺少充分画像依据时错误放行。GENERAL（通用匹配）不代表必备资格已逐项核实。
- 精简日志缺少判定依据，导致误投难以追溯；需要将最小判定审计与名单开关分开设计。

上述问题均未修复。完整范围、必备/优先/任选条件的区别和验收标准见[已知问题](docs/KNOWN_ISSUES.md)。当前不应按无人值守的可靠筛选系统使用。

## 安装

请先阅读[安装说明](docs/INSTALL.md)。正式浏览器命令要求带项目补丁的agent-browser，**不会自动下载或运行浏览器引擎**。

```bash
uv sync --locked
cp .env.example .env
cp config/preferences.example.yaml config/preferences.local.yaml
cp config/candidate.example.yaml config/candidate.yaml
```

填写真实画像、检索条件和个人期望月薪；模型服务设置仅存本机`.env`。示例不是任何用户的真实画像。不要提交个人配置、密钥、日志或简报。

```bash
# 新用户配置；不会启动投递
uv run job-agent configure
# 简历接收与待确认画像，使用本机配置的DeepSeek
uv run job-agent resume-intake /本机路径/简历.pdf
# 检查配置与安装；不连接浏览器
uv run job-agent doctor
# 只读评审，不收藏或沟通
uv run job-agent scan --engine model --limit 5
# 显式目标沟通人数；请先小范围核对结果
uv run job-agent apply --count 1 --limit 5 --no-record-lists
# 不连接浏览器或模型，更新今日简报
uv run job-agent brief
```

`--count`默认50，允许0–150且不能超过本机今日剩余；`--limit`是独立评审上限，默认200，沟通目标优先停止，仍受评审/滚动安全上限以及无新岗位、异常停止条件约束，不保证凑满人数。0沟通目标不启动浏览器。名单默认关闭，`--record-lists`可开启。

简报保存在`daily_briefs/`，同日一份，累计在前，各次实际运行按分钟分段；开启的成功收藏/沟通名单放末尾，跳过只计数。

## 当前边界

- 目前支持的城市为上海；筛选字段和值见`browser/filters.py`的选项表。未支持的非空条件会停止，不静默忽略。
- 响应与DOM核对只覆盖当前已取得的数据；没有响应时保留降级来源及完整性标记。模型判断不代表招聘方认可或所有任职资格均已满足。
- 简历目前支持文本PDF和Word `.docx`；扫描PDF、旧`.doc`不支持，不以模型OCR猜测内容。详见[配置与简历](docs/PROFILE.md)。
- 本机额度不包含用户在其他设备的手动沟通，不等于官方实时剩余。未知尝试占额度，禁止自动重试。
- 每次沟通使用平台现有打招呼流程，不追加消息、附件或自动跟聊。
